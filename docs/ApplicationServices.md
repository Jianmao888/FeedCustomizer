# 设置、捐赠与地区服务

这三个功能已从泛化的 `Core/Tools` 拆出。应用规则与契约位于对应的 Core 功能目录，Windows 存储、Store、注册表和系统策略读取位于 `Core/Infrastructure`。ViewModel 接收应用服务，窗口、Dispatcher、主题应用与确认对话框由页面或 `Presentation` 处理。

## 生命周期与组合

- `App` 持有一份 `IAppSettings`，主窗口和页面使用同一入口。
- `MainWindow` 持有一份 `DonationService` 与 `RegionService`。地区查询、缓存与修改在服务内部串行执行，确认对话框不占用服务锁。
- 设置页离开或窗口关闭时，取消许可证查询及捐赠命令、尚未进入地区修改的请求。事件处理器观察取消和异常，后台任务不直接操作绑定状态。
- 设置确认请求将取消传递给 UI 调度和弹窗串行锁，尚未显示的确认框不会在页面离开后补弹；已显示的确认框在 UI 线程关闭，完成清理后再结束等待。
- 不再使用全局 `RegionDataService` 或 `LastDiagnostics`。地区结果中的诊断只属于当前操作。

## 设置持久化

`AppSettingsService` 负责既有键的类型判断和默认值恢复，`WindowsSettingsStore` 只负责 `ApplicationData.Current.LocalSettings` 读写。读取与写入失败向调用方传播。

| 键 | 类型 | 既有默认值 |
| --- | --- | --- |
| `AppTheme` | 字符串 | `System` |
| `AppMaterial` | 字符串 | `Mica` |
| `IsFirstRun` | 布尔值 | `true` |
| `AutoEnableDeveloperMode` | 布尔值 | `false` |

缺失或类型错误的值仍会写回既有默认值；没有变更持久化位置、键名或保存格式。主题与材质通过 UI 请求事件应用，ViewModel 不再访问主窗口或控件。

## 捐赠者版

许可证查询返回已购买、未购买、失败或超时，后两者不能代表未购买。默认查询期限为五秒，超时取消平台查询并结束应用等待；未及时结束的查询仍会观察后续故障。

购买保留调用方的 UI 上下文和窗口所有者绑定，不自动重试，不用许可证查询的短期限限制 Store 购买界面。Store 返回取消与页面生命周期取消分别表达。查询失败保留已确认的购买状态，购买成功也不会被较晚返回的旧查询覆盖。

## 地区状态与修改

设备区域的 Windows 读取与欧盟分类分别由平台适配器和纯规则负责。系统策略按 JSON 对象定位唯一目标，拒绝目标身份或状态的歧义，不跨对象查找 `defaultState`。无法读取或识别时返回未知与诊断，不永久缓存失败。

策略修改复用现有 `RegionPolicyPowerShellAdapter` 和统一执行器，保留既有 UAC、超时、权限恢复和退出码处理。取消可停止锁等待和尚未开始的操作；进入平台修改后不再把页面取消传给会终止进程的执行器，等待其在既有两分钟超时内完成并恢复权限。服务持续观察任务并保持串行锁，修改或恢复未结束时窗口暂缓关闭；已离开的页面不再展示本次结果。

成功后更新服务缓存；返回主页时刷新地区警告。查询规则仍保持保守行为：只有明确的非欧盟地区且策略未确认启用时才展示警告。

## 验证范围

独立回归项目链接应用服务与策略解析实现，通过存储、Store 和地区平台替身验证默认值、失败语义、取消、缓存和串行行为。UI 调度使用显式控制的 Dispatcher 替身验证取消与队列时序。退出码转换测试只使用替身执行器，不修改真实系统策略或注册表，也不发起真实购买。

主项目使用 `CoreBuild` 编译验证，避开旧 `BeforeBuild` 发布目标对 `Resources` 的重写。AOT 发布、MSIX 打包、真实购买及系统策略修改需要独立的 Windows 集成验证。
