# Provider 部署与资源维护

本次重构保持已发布版本的目录布局。更新不搬迁订阅源或图片，不保存旧程序副本，也不在失败后重新注册旧版程序。

## 目录职责

| 目录 | 职责 | 访问方式 |
| --- | --- | --- |
| 安装包 `Resources` / `Assets` | 只读模板、程序和静态资源 | C# 读取 |
| `ApplicationData.Current.LocalCacheFolder/Local/FeedCustomProvider` | 用户配置及图片的唯一来源、可写工作副本 | C# 读写；原有 LocalFolder/未打包回退保持不变 |
| `%LocalAppData%/FeedCustomProvider` | 可重建的实际注册副本 | 包外 PowerShell 读取、发布、校验和清理 |

私有目录的 `AppxManifest.xml` 继续保存订阅源。上传/下载图片显式写入其 `Images` 子目录，预览也从这里读取。真实注册目录不参与配置恢复，只有清理时可以读取它的清单以保留正在使用的图片。

MSIX 的文件系统虚拟化不能仅凭 full trust 判断是否关闭。因此应用进程不再直接读取真实目录以判断部署版本。包外文件访问仍需要在正式 MSIX 安装环境验证，调试版的文件视图不能代替该验证。

当前用户的 Provider 注册状态查询与卸载使用 Windows `PackageManager` API，按模板清单中的包名和发布者定位，并使用完整包名卸载。注册仍使用 PowerShell `Add-AppxPackage`；注册版本的文件访问仍由包外 PowerShell 处理，以避开应用进程的 MSIX 文件系统虚拟化。卸载 API 请求一旦发起便不可取消，部署锁须覆盖其完成及随后的限次状态确认。

## 唯一入口和状态机

`ProviderDeployment.Current` 持有进程级 `ProviderDeploymentCoordinator`。启动检查/准备、启用/关闭、保存并应用、图片清理共用协调器内部的一把锁。文件适配器和 PowerShell 适配器不再各自持有业务锁。

正常部署顺序：

1. 检查并处理上次中断的操作，查询真实注册状态。
2. 仅在应用启动时检查工作版本；不完整或模板更新时修复，保留私有清单中的全部订阅源和自定义图片。检查或修复成功后复用现有版本清单，运行期间不再扫描工作目录。
3. 用户点击应用时，原子保存私有配置；部署失败不会撤销已保存配置。
4. 程序和静态资源摘要取自启动时已读取或重建的工作版本清单，只重新计算 XML 和配置图片摘要。继续检查注册版本，生成“无需发布、仅配置发布、完整发布”之一；已注册且一致则结束，不重复注册。
5. 在 `.deployment/candidate` 构建计划所需文件，并始终携带完整的预期版本清单。仅配置发布只复制变化的 `AppxManifest.xml` 和当前源引用的变化图片；首次启用、模板变化、程序或静态资源不一致时构建完整候选。
6. 写操作日志，然后卸载旧注册，确认卸载完成并停止已验证路径的 COM 进程。
7. 仅在需要注册时，通过注册表 API 预检查开发者模式；检查在卸载、停止之后且生成执行脚本之前。关闭操作或已注册且无需更新时不检查、不提示。
8. 包外 PowerShell 复用规划结果和 C# 候选校验，检查路径及复制文件集合后逐文件替换；文件操作全部成功后最后写入版本清单，不重复计算候选或注册文件的哈希。
9. 普通路径在同一包外 PowerShell 进程注册；临时开发者模式路径仅发布文件，发布成功后单独提权注册。任何发布失败均禁止注册。API 确认查询可见后标记操作完成。

启动探测和修复是工作版本完整性检查的唯一入口，同一进程重复页面初始化复用结果。修复直接按正常文件操作执行，失败向上传递；未成功初始化时禁止保存或部署，点击应用不会自动重新扫描或重建工作目录。单纯关闭不要求模板或配置可读，避免资源损坏时连关闭操作也无法完成。

部署根目录包含用户历史图片，不能整体清空或整体交换。发布采用“候选先校验 → 单文件临时写入/替换 → 注册”，不宣称多文件发布具有整体原子性。只有完整发布时，程序专属 `FeedProvider` 子目录的旧运行时产物会按当前清单移除。

仅配置发布要求规划阶段确认模板身份和注册版本的程序、静态资源都匹配；注册版本元数据缺失或损坏、程序文件漂移、发现多余运行时文件时改用完整发布。运行时不校验工作目录，也不在构建候选前全量比较工作版本；只校验实际复制的候选文件。完整发布仍会复制并验证候选中的程序文件。旧引用图片不随配置发布直接删除，仍由图片清理回收。

正常配置发布不会读取工作版本的程序或静态资源内容，配置摘要仅用于差异比较。运行期间工作文件缺失或外部修改不触发自动修复；必要文件的读取、复制及候选验证仍会报告错误，工作目录的完整检查和修复留到下一次启动。已有版本清单只在当前存储实例中复用，不新增摘要文件、缓存服务或全局状态。

规划、候选验证、卸载和发布始终处于同一把部署锁内，本应用不会在期间改写另一份候选或发布另一版本。发布阶段以文件操作成功作为依据；复制失败会中止注册并进入原有补偿流程。锁不阻止外部程序修改文件，规划后未复制文件的外部变化不会在本次发布重复检测，后续完整规划仍可发现并选择完整发布。注册成功不等价于所有文件内容已重新通过哈希验证。

单独发布和组合脚本共用发布片段及结构化诊断，分别记录发布片段和普通注册片段的耗时；总耗时还包含 PowerShell 启动等开销。发布失败时注册片段耗时为空，启动失败或超时也可能缺少片段计时，不能把缺失值当作零耗时。临时开发者模式注册单独记录总耗时，普通注册片段计时不包含该操作。

## 开发者模式预检查与兜底

注册前由 `DeveloperModeRegistry` 直接读取 HKLM 的 `AppModelUnlock/AllowDevelopmentWithoutDevLicense`，不启动 PowerShell，也不缓存开关状态。该值只用于预判；系统策略或检查后的外部修改仍可能导致注册失败，应用不修改组织策略。

| 状态 | 自动开发者模式设置 | 路径 |
| --- | --- | --- |
| 已开启 | 任意 | 一次普通 PowerShell 发布并注册 |
| 未开启或设置项缺失 | 开启 | 普通发布，再单次提权临时开启、注册、恢复 |
| 未开启或设置项缺失 | 关闭 | 不发布、不注册，补偿后返回已有确认弹窗 |
| 读取失败或值类型异常 | 任意 | 记录诊断并尝试普通发布、注册 |

普通注册阶段出现 `0x80073CFF` 时，若允许自动开发者模式，协调器只重试一次提权注册，不重复发布；否则返回同一个确认状态。发布错误和其他注册错误不触发提权。提权失败或 UAC 取消直接结束，不再次返回确认状态。

用户拒绝确认后结束，旧包已卸载，源显示关闭，已保存工作配置保留。用户同意后启用自动设置，并携带本次已确认的意图重新进入完整串行部署事务，直接选择临时开发者模式路径，即使读取曾经失败也不再尝试普通注册。不跨弹窗保持事务、锁或全局确认标记。

普通与提权注册复用同一 `Add-AppxPackage` 片段。临时开启及恢复在同一提权脚本中完成，以脚本执行时读取的原值和类型为准；原值缺失时删除临时值。正常异常路径会执行 `finally` 恢复，操作错误与恢复错误同时保留。进程强制终止无法保证 `finally` 执行，因此不能把异常恢复承诺扩展到强制终止场景。

## 版本与中断日志

- `.deployment-version.xml`：包含格式版本、模板身份和受管理文件的 SHA-256。模板身份包括包版本、进程架构和全部模板内容，支持相同包版本号的开发重建。
- 私有根目录的版本清单记录工作资源准备版本。启动读取或重建后在进程内复用；订阅源可以随后编辑，因此每次规划只更新配置/引用图片摘要，重新生成完整目标版本清单。
- 实际注册目录的版本清单仅在所有文件成功发布后写入；是否注册成功仍以 AppX 查询为准。
- `.deployment/operation.xml`：记录操作阶段，包含卸载、发布、注册、验证、提交和完成等状态。失败未完成补偿时保留日志。
- `.deployment/prepared`、`.deployment/candidate`：当前版本的临时候选；仅配置候选可以不含程序和静态资源，但始终包含完整预期版本清单。它们不是旧版本备份。

旧安装没有新版本清单时，保留已有私有配置和图片，原地准备资源。旧 `.first_run_complete` 不再参与判断，也不需要借助它迁移数据。若用户清单损坏，准备立即失败，原文件不被空模板覆盖。

## 失败与补偿

- 准备/候选阶段失败：现有注册仍保持原样。
- 进入卸载/发布后失败：尽力停止未完成注册，不回滚旧程序。工作配置和当前版本候选仍可用于下一次重试。
- 补偿成功：返回 `ProviderDisabled`；界面提示重新启用以部署当前版本。
- 补偿失败：返回 `Failed` 和单独的补偿诊断，注册状态为空（未知），日志保留。不得把它显示为确定关闭。
- 进程中断：下次调用协调器时先处理日志；已完成只清日志，未完成先停止不完整注册，再允许后续操作。
- 开发者模式确认和 UAC 取消仍以稳定结果分类返回 UI，底层不弹对话框。

返回结果分别包含原失败阶段、原始诊断、配置是否已保存、补偿结果、补偿诊断和可确认的注册状态。自动恢复不主动重新注册旧包。

## 图片清理

启动完成后以及成功应用配置后触发。先取 UI 当前编辑和待删除列表的引用快照，再进入部署锁：

1. 有未完成部署日志时暂停清理。
2. 合并当前编辑、私有清单、包内默认资源的图片引用。
3. Provider 仍注册时额外保护实际清单的引用；已卸载时旧清单不永久阻止清理。
4. 任何必要引用清单读取失败时跳过清理，绝不把读取失败当作“没有引用”。
5. 私有 `Images` 由 C# 清理，真实 `Images` 由包外 PowerShell 清理；两边使用相同保留集合。
6. 只删除目录第一层超过 24 小时且无引用的普通文件，保留默认图片、所有模板图片及新上传/下载文件。宽限期用于保护图片下载和页面切换中的引用空窗。

清理结果包含删除数量及失败诊断；清理失败是非致命维护问题，不改变注册结果。引用仍存在、文件尚新或被占用时，下次触发再检查。

## 验证

执行 `dotnet run --project Tests/Deployment.Tests/Deployment.Tests.csproj`。测试直接链接真实协调器、文件版本逻辑、清单逻辑、存储实现和 PowerShell 文件适配器；包元数据和 AppX 使用替身，文件脚本只在独立临时目录运行。测试不会改动机器的真实 AppX 注册、注册表或 UAC。`PackageManager` 的权限和真实卸载结果只能在打包安装的测试账户或虚拟机中验证。

发布前在可恢复的测试账户/虚拟机检查：

- 已发布旧版（含自定义图片/多条订阅源）升级后，配置数量与图片显示不变，实际路径不变。
- 首次安装、版本不变重建、关闭后重新启用、更新后首次启动。
- 保持 Widgets 使用 Provider 时更新；检查进程退出、卸载查询和最终 Widgets 列表。
- 检查当前用户的 `PackageManager` 查询权限、卸载权限及延迟可见性；比较启用、关闭和保存配置前后的查询/卸载耗时与 PowerShell 进程次数。
- 确认卸载散文件注册后，注册版本目录中的程序和静态资源仍可用；只改源配置或图片时检查这些文件的内容与修改时间不变，并记录候选构建及发布耗时。
- 注册失败、拒绝 UAC、发布文件被占用时的提示；解除占用后重新启用可以部署当前版本。
- 开发者模式分别开启/关闭、自动设置分别开启/关闭时启用和修改配置；关闭源不提示，拒绝确认后源关闭，同意后直接提权注册。记录普通注册调用次数及 UAC 前耗时，结束后检查系统开关恢复原值。
- 在发布/注册阶段终止应用，再启动时日志能被处理，不注册旧程序。
- 在两个 Images 目录分别放入过期孤儿、默认图、当前引用图和草稿图，确认只删除孤儿。

真实 MSIX 更新、UAC 及 Widgets 界面需要以上集成验证，不能仅凭编译和替身测试宣称通过。
