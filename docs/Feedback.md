# 日志导出与反馈

## 目录与数据所有权

应用日志仍以 MSIX 私有数据目录中的 `Local\Logs` 为唯一来源。日志导出只读取该目录顶层的 `FeedCustomizer-*.log`，不会包含 Provider 清单、订阅源配置、用户图片或注册目录文件。

ZIP 先使用随机名称在 `ApplicationData.TemporaryFolder` 中完整构建，再复制到用户下载目录。临时文件在 `finally` 中按已验证的精确路径删除；复制失败时还会尽力删除不完整的下载文件。成功导出的 ZIP 属于用户文件，不受应用日志的 14 天保留策略管理。

当前日志仍可能由 Serilog 追加。归档器以共享读取方式打开每个文件，并且只复制打开瞬间的长度，避免中断应用日志或因为持续追加而无法结束。日志目录为空时，ZIP 中写入 `ExportInfo.txt`，用于说明日志系统可能未初始化。

## 邮件通道

邮件能力只保留一层 `IFeedbackMailTransport` 接口。当前实现按以下顺序调用：

1. Simple MAPI：请求默认的兼容客户端创建纯文本邮件并附加 ZIP；
2. `mailto:`：MAPI 不受支持或启动失败时的降级，只能预填收件人、主题和正文，附件需要用户确认或手动加入。

邮件客户端接管后，应用不跟踪用户是否编辑、关闭或实际发送邮件。Simple MAPI 返回用户终止时视为客户端已经处理，不继续打开第二个邮件窗口。只有所有通道都无法打开客户端时，应用才提示用户手动发送已经导出的 ZIP。

未来如需针对特定客户端适配，应新增 `IFeedbackMailTransport` 实现，并由 `FeedbackMailDispatcher` 调整优先级；设置页和错误弹窗不得直接依赖具体客户端。

## 隐私与本地化

反馈邮件的收件地址和固定反馈 UUID 位于应用常量类中。邮件正文、隐私提示、错误来源和按钮文字均从当前语言资源加载。正文会说明日志可能包含系统版本、应用版本、操作阶段、脱敏路径和 PowerShell 诊断，并提供 ZIP 的完整路径，便于附件未自动加入时由用户手动选择。

邮件正文不复制完整异常、用户输入 URL 或 PowerShell 原始输出。此类诊断只通过现有日志脱敏与限长规则写入 ZIP。

## 错误弹窗

Provider 部署、启动或资源准备、地区策略、Widget 数据清理、网页图标和捐赠购买失败使用统一的可反馈错误弹窗。弹窗先准备日志归档，成功后关闭并打开邮件客户端；归档失败时在当前弹窗内显示状态，避免再叠加错误框。

日志导出和邮件启动功能自身的错误不再提供“发送反馈”，防止递归失败。所有邮件通道失败时允许显示第二个普通提示，其中包含 ZIP 完整路径和反馈邮箱。
