# 窗口位置与大小维护说明

窗口初始布局和恢复由 `MainWindow.Placement.cs` 适配 Windows App SDK，纯计算规则位于 `Core/Windowing/WindowPlacement.cs`。窗口位置属于 UI 生命周期，不进入 ViewModel。

## 默认布局

没有有效记录时，窗口保持 `560 × 800` DIP，并在主显示器工作区居中。某个方向无法容纳窗口时，该方向固定到工作区起点，不缩小窗口；因此超高或超宽窗口的左上角仍然可见，右侧和底部允许超出屏幕。

## 恢复与保存

- 设置以 `ApplicationDataCompositeValue` 保存在 MSIX 私有 `LocalSettings` 中，字段作为一个整体替换。
- 状态保存物理坐标、物理尺寸、保存 DPI、结构版本和最大化标记。
- 恢复时先选择与旧矩形最近的有效显示器，再按目标显示器 DPI 换算尺寸。
- 恢复时只把左上角校正到目标工作区以内，不限制右边缘和下边缘，也不会缩小窗口。
- 最大化状态会恢复；最小化状态不会恢复。
- 拖动和缩放只更新内存快照，只有窗口关闭真正获准后才写入设置。
- 状态损坏、读取失败或显示器信息不可用时回退默认布局并记录日志，不阻止应用启动。

## Native AOT 约束

显示区域、移动、缩放和窗口状态优先使用 Windows App SDK。获取窗口 DPI 与现有窗口过程子类化继续使用 `LibraryImport` 和 blittable 结构，不使用运行时反射封送。`WM_GETMINMAXINFO` 每次按窗口当前 DPI 计算 `560 × 500` DIP 的最小尺寸，以支持跨不同缩放比例显示器。
